The design predicted exactly what was observed. That is the opposite of a contradiction.

### R-02 — "Empty evidence windows will corrupt recovery decisions"

**Rejected on inspection. The guard exists and is load-bearing.**

```python
# health_policy_evaluator.py:190-198
total = self.sample_count(stats, policy)
if total < int(policy.minimum_samples):
    return self._decision(capability_id, RecoveryAction.NO_ACTION,
        f"insufficient samples: {total} < minimum_samples={policy.minimum_samples} in window", stats)
```

Plus `HealthPolicy.__post_init__` enforcing `minimum_samples >= 1`
(`policy.py:107-111`), plus an empty `POLICIES` registry yielding `NO_ACTION`
for any unregistered capability.

Under-observation degrades to **inaction** in both directions — no false
quarantine, no false recovery. This was the most promising candidate in the
survey; it was tested against the code and it does not hold.

### R-03 — "The evidence stores cannot distinguish *nothing happened* from *nobody was watching*"

**Rejected as a contradiction; retained as an observation.**

The representational gap is real: no frozen artifact records "observation was
active over window W", so an empty `HealthEvidenceStore.query(...)` is
semantically ambiguous to a future reader.

But the gap has **no consequence the design cannot absorb**, because of R-02:
ambiguity resolves to `NO_ACTION`, which is the honest answer under either
interpretation. F2 requires an observed contradiction, not an aesthetic
incompleteness. Absent a runtime fact that this ambiguity *misled* something,
this does not qualify.

*Re-examine if and when observation is ever enabled and a window is read across
an activation boundary.*

### R-04 — G-01 `capability_gateway_mode` unreachable from config

**Rejected as a contradiction; recorded as an activation gap.**

Hard-verified (pydantic 2.13.4, `extra` defaults to ignore):

```
CapabilityLayerConfig(capability_mode=True, capability_gateway_mode=True)
  declared fields : ['capability_mode', 'pilot_capability_allowlist']
  getattr(...)    : ABSENT -> False
```

`config.yaml` entries for this key are silently discarded. However:

- the frozen assumption is *"activation is config-gated, **default OFF**"* — and default-OFF is **preserved**, indeed enforced more strongly than intended;
- the design **can** represent the fix (add a field to an existing model); no frozen boundary obstructs it;
- programmatic activation via the explicit `capability_gateway_mode=` kwarg still works, and is how every test drives it.

This is an implementation gap, and implementation gaps are F-slice work, not
Foundation evolution. It is nevertheless the **first obstacle any future
activation slice will hit**, and is flagged for that reason.

### R-05 — N-01 two subsystems named "health"

**Rejected as a contradiction; recorded as an adjacency risk.**

`anima/core/health_history.py` is constructed unconditionally
(`anima_core.py:44-45`), is deployed, and is actively writing
`data/health_history.json` right now. `anima/capability/health/` is dormant and
undeployed. Their schemas share no field
(`running/watchdog_lag_sec/llm_failures` vs `capability_id/observed_at/normalized_outcome`).

They are genuinely different objects, so there is no contradiction — process
liveness is not capability health. The risk is **conflation by a future reader**,
amplified by the fact that **no F8 document mentions `health_history` at all**,
including F8.10 §6 which is presented as a 持久化资产盘点.

### R-06 — N-02 F8.10 §6 inventory conflates mechanism with effect

**Rejected as a contradiction; recorded as documentation precision.**

F8.10 §6 tabulates resolution audit and transition as `✅ 持久化` and health
evidence as `无`, and Q5 reasons from that asymmetry to "therefore build an
independent HealthEvidence store". Operationally the asymmetry does not exist:
all three are at zero, because ✅ there denotes *a persistence mechanism exists
in code*, not *persistence is in effect*.

The Q5 conclusion is still sound on its own terms (a store must exist before it
can be wired). Only the stated justification is imprecise. Documentation-level;
no design change implied.

## 3. Why nothing was promoted

Promotion to F2 requires the frozen design to be **unable to express** an
observed fact. Every fact F9.1 observed is a fact of **absence**, and absence is
already fully expressed by the frozen design:

| Observed | Design element that already represents it |
|-|-|
| No resolution samples | F8.7 opt-in injection, form (a); F8.13 §9 *"❌ ResolutionEvent 强制耐久化（保持 opt-in）"* |
| No health samples | F8.10.1 deferred wiring; `health_evidence_sink=None` default = "行为逐字节不变" |
| No transitions | F8.12 §4.3 empty registry ruling; no daemon (R3) |
| Nothing runs on a timer | F8.13 §6 *"无 daemon / timer / polling"* |

Manufacturing a contradiction out of this material would corrupt the very
protocol it feeds. The Foundation stays frozen.
