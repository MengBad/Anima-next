# F9.2 Operational Observation Activation — Scope Freeze & Activation Design Freeze

> 派生自 `f9.1_operational_validation_scope_freeze_v0.1.md` 的「INCONCLUSIVE BY CONSTRUCTION」结论。
> F9.1 证明：**没有足够 observation window 支持任何 Foundation Evolution（F2 触发条件 NOT MET）**。
> F9.2 是**下一个独立入口**：把「观察能力」从休眠态激活为可用态——**只启用观测，不改执行语义**。

- 授权：`F9.2 Operational Activation Full Slice Authorization`（一次授权跑完 Scope Freeze → Implementation → Validation → diff audit → single commit → STOP）。
- 边界：`F9.2 = Operational Observation Activation`；**NOT** Architecture evolution / Policy tuning / Recovery automation / Resolver integration / Foundation Evolution。
- 纪律链：`baseline → facts → RED → implementation → positive evidence → negative boundary → regression → diff audit → single commit → STOP`。
- 验收硬门槛（四零 diff）：`Resolver diff = 0` / `CapabilityContract diff = 0` / `HealthEvidence schema diff = 0` / `Lifecycle semantics diff = 0`。

## Phase 1 — Scope Freeze（冻结「允许观察什么」）

### S1 Evidence Sink Activation

| Sink | 处置 | 依据 |
|-|-|-|
| `HealthEvidenceStore` | **全量接线** | 实时通道：`_emit_health_evidence` 在受治理 route 后发射 |
| `Resolution Audit Sink`（`PersistentAuditSink`） | **全量接线** | 实时通道：Gateway 构造时把 `_governance_audit_sink` 注入 resolver（`tools/__init__.py:326`） |
| `TransitionStore` | **构造 + 接入 dormant `HealthObserver`** | recovery 路径当前未运行时接入（F9.1：0 transition、observer 零构造）；本 slice 把 store 建成并挂接，使 audit visibility seam 可用 |

条件（全部遵守）：
- append-only（三个 store 均为 JSONL append-only，已实现）。
- 不参与 execution path（sink 是旁路，fail-open）。
- 不改变 resolver（`runtime/capability_resolver.py` 零改动）。
- 不改变 policy decision（不引入/修改 evaluator/policy）。
- **禁止**：sink → runtime control / sink → lifecycle mutation / sink → provider selection。

裁定（TransitionStore observer accessor）：
- `anima.capability.resolver.CapabilityResolver`（M0.3 骨架）**无** `lifecycle_for`；该方法仅在 `anima.runtime.capability_resolver` 的运行时 resolver 上。
- observer 的 `lifecycle_accessor` 采用轻量 `lambda cid: CapabilityLifecycle(cid)`（每调用新建，足以完成审计记录：report_unhealthy 见 REGISTERED → 转 QUARANTINED → 落盘）。
- **权威 resolver-backed accessor 留待 recovery 运行时激活 slice 接线**（属跨边界问题，本 slice 只记 deferred，不实现）。
- 此简化**不改变 lifecycle 语义**：observer.recover 仍只接受 `QUARANTINED→ACTIVE`；本 slice 不新增/修改任何 transition 边。

### S2 Observation Window

冻结：
- window 语义（store 以 `observed_at=time.time()` / `transition.at` 为基准，已实现）。
- timestamp 来源（emission 时刻，已实现）。
- retention contract（`retention_days=30` 默认、显式 `cleanup()`，已实现）。

不冻结（本 slice 不动）：
- production threshold / recovery threshold（属 policy tuning，超出范围）。

原因：F9.2 目标是**产生 evidence**，不是调参。

### S3 Data Boundary（延续 F8.11 metadata 红线）

允许记录（store 现仅写这些字段，已核验）：
- `capability_id` / `execution_key` / `normalized_outcome` / `error_class` / `timestamp` / `transition reason`。

禁止（负向边界测试钉死，序列化后文件不得出现以下子串）：
- `result_fragment` / `payload` / `credential` / `secret` / `provider_secret` / `raw_exception` / `traceback` / `password` / `token`。

核验：
- `HealthEvidence` 字段：`evidence_id/capability_id/provider_id/execution_id/observed_at/selected/executed/success/error_type/duration_ms/metadata`（metadata 仅 `normalized_outcome`/`error_class`）——无禁止项。
- `ResolutionEvent` 字段：`timestamp/capability_id/execution_key/requested_version/candidates/selected_provider/metadata_snapshot/outcome/error`——无禁止项。
- `TransitionStore` 字段：`capability_id/source/target/reason/at`——无禁止项。

### S4 Production Evidence

允许：observation only（sink 落盘即观测）。
禁止：automatic recovery / automatic quarantine / routing change。
- 本 slice **不新增任何触发源**：无 daemon / timer / polling / 后台循环；recovery 仍仅由外部显式驱动（与 F8.8/F8.12 一致）。

### S5 Activation Proof

必须证明：`Observation ON → Execution behavior unchanged`。
- 验证手段：同一 governed 执行（如 `filesystem.read` 真实读文件），sink ON 与 OFF 的**返回字符串逐字节一致**；resolver 选择、`get_schemas` 输出不受影响。
- 现有 `test_c1_default_off_no_sink_parity` 已钉死 health sink 行为等价；本 slice 增补配置驱动真实 store 的同义证明。

## Phase 2 — Implementation（无 contradiction，直接进入）

仅实现：
- **sink wiring**：`create_default_registry` 按 config 构造三个 sink 并注入。
- **minimal config surface**：`CapabilityLayerConfig` 增 5 字段（默认全 OFF）。
- **evidence emission verification**：测试证明 ON 后确实收集、OFF 时零变化。

不实现：
- 新 policy / 新 evaluator / 新 lifecycle edge / resolver 修改。

配置字段（默认值全 OFF，受控重启生效 = R4 kill switch 语义）：
```python
capability_gateway_mode: bool = False      # 修复 G-01：此前未在 config 声明→被 pydantic extra=ignore 静默丢弃
governance_audit_enabled: bool = False     # 构建持久化 Resolution 审计 sink
health_evidence_enabled: bool = False      # 构建 HealthEvidenceStore
transition_audit_enabled: bool = False     # 构建 TransitionStore 并接入 dormant HealthObserver
governance_data_dir: str = "governance"    # sink 子目录（相对 persistence.data_dir）
```

接线点（均在 `anima/tools/__init__.py`）：
- `create_default_registry` 读上述 flag，基路径 = `core.config.persistence.data_dir / governance_data_dir`；enabled 时构造 `PersistentAuditSink` / `HealthEvidenceStore` / `TransitionStore(+HealthObserver)` 并注入 registry。
- `ToolRegistry` 增 `health_observer` 属性（默认 None；由 create_default_registry 在 enabled 时设置）。
- 路径构造需 `from pathlib import Path`。

## Phase 3 — Validation

链：`baseline → RED → implementation → positive evidence → negative boundary → full regression → diff audit → single commit → STOP`。

测试文件：`tests/test_f9_observation_activation.py`（新建，随 slice 单提交）。
- RED：config 启用但 wiring 缺失 → `registry._health_evidence_sink is not None` 失败。
- positive：真实 governed 执行 → 真实 `HealthEvidenceStore.query()` 得 1 条；`PersistentAuditSink.store.read_events()` 得 1 条；`health_observer.report_unhealthy` → `observer._store.query()` 得 1 QUARANTINED。
- negative（S3）：读三 store 原始 JSONL，断言禁止子串全部缺席。
- S5：sink ON vs OFF 返回字符串一致。

diff audit 验收：
```

CapabilityContract diff = 0  （contracts 不触碰）
HealthEvidence schema diff = 0 （HealthEvidenceStore/model 不触碰）
Lifecycle semantics diff = 0 （lifecycle.py / observer 的 recover 边不改动）
```
