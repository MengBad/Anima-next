## 1. Task Breakdown

Eight executable tasks derived from Engineering Plan S1–S5. Each task lists **Inputs / Outputs / Completion Criteria / Dependencies** only. Where a task's concrete approach is an open implementation decision, it is flagged `DEFERRED (Dx)` and left undecided.

### Slice 1 — Plan data-contract completion

#### T1.1 — Extend `Plan` dataclass with RFC-0002 §5 identity + §7 lifecycle fields
- **Inputs:** RFC-0002 §5 field definitions (`id` / `contract_version` / `goal_ref` / runtime `status` …); §7 runtime-state definitions (`draft → active → superseded → deprecated`); existing `Plan` fields from RFC-0106 (`goal_target`, `task_graph`, `ordering`, `branching`, `rollback`, `context_ref`, `emphasis`, `focus`).
- **Outputs:** Extended `Plan` dataclass carrying the new identity + lifecycle fields; existing fields unchanged.
- **Completion Criteria:** `Plan` carries all required fields with safe defaults; existing `derive_plan` return shape remains backward-compatible; **no persistence added** (Plan stays Transient-Derived, never stored).
- **Dependencies:** none (Foundation frozen; M0.4.x gate READY).
- **Files (listed only, not modified here):** `anima/constitution/state.py`.

#### T1.2 — Add RFC-0002 §5 `Task` representation inside Plan
- **Inputs:** RFC-0002 §5 Task (`capability_need` / `depends_on` / …); existing `AgentTask` / `Step` / `core.tasks.Task` as **non-authoritative** references only.
- **Outputs:** A `Task` representation usable as a Plan's single executable unit.
- **Completion Criteria:** `Plan` can hold an ordered set of RFC-0002 `Task`s; each `Task` carries `capability_need` + `depends_on`.
- **Dependencies:** T1.1.
- **DEFERRED (D2):** placement of the `Task` representation (new dataclass vs nested) is an implementation decision — **not decided here**.
- **Files (listed only, not modified here):** `anima/constitution/state.py` [+ possibly `anima/constitution/planner.py` if construction helpers are added].

### Slice 2 — Planning Interface implementation

#### T2.1 — Implement Planning Interface operations on the Planning Authority owner
- **Inputs:** RFC-0002 §6 interface semantics (`activate_plan` / `revise_plan` / `invalidate_plan` / `read_plan` / `list_plans`); §7.1 transition ownership; existing `Planner` (`build_plan` / `cancel_plan` / `active_plan`).
- **Outputs:** `Planner` gains the five §6 operations; single-writer (O1) enforced.
- **Completion Criteria:** each op behaves per §6 / §7.1; non-owner call raises; no upstream Goal/Drive/Context mutation occurs.
- **Dependencies:** T1.1, T1.2.
- **Files (listed only, not modified here):** `anima/constitution/planner.py`.

#### T2.2 — Implement in-memory PlanRegistry + single-writer guard
- **Inputs:** RFC-0002 §6 registry semantics; O1 single-writer; existing `Planner._active_plan` (holds exactly one Plan).
- **Outputs:** A registry holding Plans in-memory; a guard rejecting concurrent writers.
- **Completion Criteria:** registry stores/retrieves Plans **in-memory only** (no persistence); guard verified to reject non-owner writes.
- **Dependencies:** T2.1.
- **DEFERRED (D3 / R5):** registry placement (module-level in `planner.py` vs dedicated `plan_registry.py`) and single-vs-multi Plan semantic are implementation decisions — **not decided here**.
- **Files (listed only, not modified here):** `anima/constitution/planner.py` [or new `anima/constitution/plan_registry.py` — D3 deferred].

### Slice 3 — `derive_plan` as canonical constructor (wiring)

#### T3.1 — Wire `derive_plan` as the single `p`-derivation constructor feeding RFC-0002 Plan
- **Inputs:** `constitution.derive_plan` (pure function, implemented, UNWIRED); `agent.TaskPlanner._decompose` (LLM backend, implemented); RFC-0002 §4 / §5.
- **Outputs:** A construction path `request → RFC-0002 Plan` via `derive_plan`.
- **Completion Criteria:** a compliant `Plan` is produced through `derive_plan`; determinism preserved (same inputs ⇒ same Plan); LLM decomposition feeds the task-graph.
- **Dependencies:** T2.1, T2.2.
- **DEFERRED (D1):** the concrete integration shape (how `TaskPlanner` relates to `derive_plan` — e.g. decomposer-inside vs adapter) is an implementation decision — **not decided here**. This task establishes the path; it does not pre-select the approach.
- **Files (listed only, not modified here):** `anima/constitution/planner.py` (derive_plan wiring); `anima/agent/planner.py` (TaskPlanner backend).

### Slice 4 — Runtime wiring

#### T4.1 — Replace/adapt runtime `TaskPlanner.plan()` call sites to obtain RFC-0002 Plan
- **Inputs:** Call sites `AgentExecutor` (`anima/agent/executor.py`), `OwnerAgent` (`anima/agent/owner_agent.py`), `anima_core.py`; Planning Interface (T2/T3 output).
- **Outputs:** Runtime path that obtains a compliant `Plan` via the Planning Interface.
- **Completion Criteria:** call sites produce/consume an RFC-0002 `Plan`; no regressions in existing `AgentExecutor` / `OwnerAgent` behavior.
- **Dependencies:** T3.1.
- **DEFERRED (D1 / D2):** whether `TaskPlanner` is replaced or adapted, and the `Task` representation, are implementation decisions — **not decided here**.
- **Files (listed only, not modified here):** `anima/agent/executor.py`; `anima/agent/owner_agent.py`; `anima_core.py`; `anima/agent/planner.py`.

### Slice 5 — Cross-authority guard + regression suite

#### T5.1 — Reinforce cross-authority invariant across new wiring
- **Inputs:** `constitution.invariants.assert_no_cross_authority_mutation`; new wiring from T2–T4.
- **Outputs:** Hardened guard calls at Plan-mutation boundaries.
- **Completion Criteria:** guard raises on any Planning-Authority attempt to mutate Goal/Drive/Context; behavior covered by a test.
- **Dependencies:** T2.1, T3.1, T4.1.
- **Files (listed only, not modified here):** `anima/constitution/invariants.py`; the call sites listed under T4.1.

#### T5.2 — Build regression + new unit/integration test suite
- **Inputs:** existing `tests/test_constitution_m1.py`; agent-level call-site tests.
- **Outputs:** New test files covering Plan construction, lifecycle, and runtime integration.
- **Completion Criteria:** all new + existing tests green; regression suite passes.
- **Dependencies:** T1.1 – T4.1.
- **Files (listed only, not modified here):** `tests/` (new files; names TBD at implementation — see Test Matrix).
