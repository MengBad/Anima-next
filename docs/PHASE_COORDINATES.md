# 阶段编号单一坐标（PHASE COORDINATES）

> **本文档的唯一职责**：终结"六套并行阶段编号"（审查 P1-6）。
> 结论是：**编号不是历史包袱，是坐标冲突** —— 六个体系里有三个用了同一个前缀
> （`M0`、`P0`、`Phase`），导致"现在做到哪一步"无法用一句话回答。
> 本文声明**每个编号管什么、谁是权威、哪些只能当历史读**。
>
> 建立于 2026-09-18。**本文档只声明坐标，不排期、不授权任何实现。**

---

## 1. 一条规则

| 问题 | 该查哪个坐标 |
|---|---|
| 「系统现在在做什么工程？」 | **执行线** `Phase 0–3`（现行）+ `Phase A–D`（差距收口，前置） |
| 「某个能力/边界的治理状态是什么？可以动吗？」 | **治理线** `M0.x`（含 `F8.x` / `F9.x` / `Phase 4.x–5.x` 子系） |
| 「这条代码/这个行为是哪一版带来的？」 | **历史线** `R*`（只作回溯，**不排期**） |
| 「这条问题有多严重？」 | **严重度** `P0 / P1 / P2`（**只是标签，不是阶段**） |

## 2. 六个体系逐个定性

| 编号 | 前缀 | 管什么 | 权威文件 | 状态 |
|---|---|---|---|---|

| `P0–P3` | P | **严重度标签**（P0 最重） | 各审查报告「分级发现」节 | ✅ 现行，但**仅是标签** |

### 2.1 两个已定性的同名冲突

1. **`M0` 撞名**：旧里程碑 `M0–M4` 与治理线 `M0.x` 共用前缀。
   → 约定：**写 `M0.x` 时必须带小数**；无小数的 `M0` 一律指旧里程碑且必须标 `[HISTORICAL]`。
2. **`P0` 双重语义**：既被当严重度（P0/P1/P2），又被当阶段名（"四层演进计划 P0–P3"）。
   → 约定：**`P0–P2` 只用于严重度**。若某文档用 `P0–P3` 指阶段，必须在同段改为
   `Phase 0–3`。这条是纯命名纪律，无行为影响。

### 2.2 一个命名碰撞（非编号，但同样误导）

`design/vision_plan.md` 里的 **vision = 视觉（多模态看图）**，与本项目的
**愿景（vision, 项目定位）** 无关。检索 `vision` 时两者会互相污染 —— 检索时用
`vision_plan` / `视觉` 与 `VISION.md` / `愿景` 区分。

## 3. 当前坐标（2026-09-18）

```
治理线 M0.x ── 冻结中，只读（F8.x 收敛 / F9.x 运营观测 / Phase 5.x 身份绑定）
                    │
                    │（互不阻塞）
                    ▼
差距线 Phase A ── 让项目说真话（声明与事实一致；无代码或极少代码）   ← 本轮
        Phase B ── 补断边（Memory→Identity 那条边）
        Phase C ── 收敛（去重与卫生；F5/pilot 二选一）
        Phase D ── 加固（数据增长 / 哑配置 / 潜伏 ImportError）
                    │
                    ▼
执行线 Phase 0–3 ── 智能提升执行单（Phase A 收口后继续）

历史线 R* ── 只读，仅用于回溯"这段代码哪来的"
```

**为什么 `Phase A–D` 排在 `Phase 0–3` 前面**：`Phase 0–3` 是"往上加能力"，
而 `Phase A` 是"先把地图改对"。三个 P0 里有两个是**声明与事实不符**而非功能缺陷 ——
在不修声明的情况下继续加能力，等于在错地图上施工。

## 4. 维护规则

1. 新文档引入新编号体系 → **必须在本表登记**，否则视为违反本坐标。
2. 退役一个体系 → 在本表把状态改为 `[HISTORICAL]`，并在该体系所有文档头部
   加 `> [HISTORICAL] 本文档停更于 YYYY-MM-DD，仅作历史参考`（沿用既有约定，
   见 `ROADMAP.md` / `PROJECT_STATE.md` / `DESIGN_COMMITMENT_TRACKING.md`）。
3. **禁止**再用 `P0–P3` 表示阶段；**禁止**用无小数的 `M0` 指治理线。
