## 1. What this Review does

Per the agreed cadence:

```
Workflow Recon ──▶ Workflow Unification Study ──▶ Study Review (this) ──▶ judge Decision Input need
                                                    │
                        ├─ not needed ──▶ RFC-0003 Draft
                        └─ needed ─────▶ Workflow Decision Input ──▶ RFC-0003 Draft
```

Three triage criteria (from brief):
1. **Governance question?** — touches canonical owner / Foundation-Frozen doc / RFC boundary.
2. **Implementation concern?** — a how-to-build detail (Retry / Queue / Checkpoint-as-runtime).
3. **Blocking Draft?** — must a human ruling land *before* Draft, or can the Draft resolve it
   (declaration + semantic alignment, as RFC-0002 did with A2)?

## 3. The one candidate (GQ1)

GQ1 is the **only** question that resembles a *blocking governance question*: it asks for the
canonical definition/scope of "Workflow" — the subject RFC-0003 is meant to specify. If left
unresolved, the Draft risks either over-scoping (swallowing all four state machines) or inventing a
definition that collides with RFC-0106's reserved Workflow interface point.

**But** the RFC-0002 precedent is directly applicable: RFC-0002's blocking item (canonical Plan
owner) was **not** solved by a pre-Draft Foundation change or a separate ruling gate — it was
resolved *inside the Draft* by **A2**: RFC-0002 declared its own Infrastructure Planning Authority,
in **semantic alignment** with RFC-0106 (which kept its ontology), with **no Foundation Evolution**
and **no pre-Draft ruling**. The same shape fits GQ1:

- RFC-0003 can declare its own Infrastructure "Workflow" owner + scope, in semantic alignment with
  RFC-0106's reserved Workflow interface point (RFC-0106 §6 / RFC-0107), without modifying Foundation.
- The other 9 questions are either Draft-resolvable (governance/RFC-internal) or implementation
  concerns, and do **not** require a human ruling before Draft.

So GQ1 is a *candidate* blocking question that, per the established A2 pattern, does **not strictly
require** a pre-Draft Decision Input — it can be handled the A2 way, inside the Draft.

## 5. Implication for Decision Input (for the human's decision)

- **Strictly required Decision Input: none.** Following the RFC-0002 A2 precedent, the only
  canonical-definition question (GQ1) is resolvable within the Draft by RFC-0003 declaring its own
  infrastructure "Workflow" owner with semantic alignment to RFC-0106 — no Foundation Evolution, no
  pre-Draft ruling.
- **If governance prefers an explicit, separate ruling for GQ1** (given Workflow's wider surface vs
  Planning), the clean form is a **minimal Decision Input covering only GQ1** — not a 10-question
  input. This avoids the RFC-0002 pattern of entering a full Decision Input and then deleting
  questions during review.
- **The other 9 questions must NOT trigger a Decision Input.** 7 are Draft-resolvable; 2 (GQ5/GQ6)
  are implementation concerns that belong in the Draft's scope/non-scope notes, not in governance.

This Review makes **no governance decision**. It only triages. Whether to proceed straight to
RFC-0003 Draft (A2-style) or to issue a 1-question Decision Input for GQ1 is the reviewer's call.
