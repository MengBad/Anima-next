# M0.5 · RFC-0003 Workflow Recon — WORKFLOW-DEPENDENCY-MAP

> **Recon discipline (per brief).** Discovery only. Facts only. The diagrams below depict
> **observed** call/persistence/reference relationships in the code. They are **not** a proposed
> architecture. No recommendation, no evaluation. Attachment to (not part of) RFC-0003.

Legend: `──▶` call/use · `──persist──▶` serialization · `──(id)──▶` string-id reference (no shared object)

---

## 1. Agent task-execution world (`anima/agent/`)

```
OwnerAgent  (orchestrator; handler "!anima agent" entry, perm ≥ 4)
   │  submit / approve / cancel / status_text
   │
   ├─▶ AgentTaskStore  ──persist──▶ data/agent_tasks.json
   │      ▲ save / get / set_status / create
   │      │
   └─▶ AgentExecutor.execute(task)
          │
          ├─▶ TaskPlanner.plan(request, task)  ──▶ LLM  (or keyword fallback)  ──▶ list[Step]
          ├─▶ _run_step(step, task, budget)     ──▶ capability / tools  (RFC-0001 dispatch)
          ├─▶ AgentTaskStore.save()            ── writes AgentTask + Step (status/current_step/context)
          └─▶ AgentAuditor.emit("agent_progress")  ──▶ audit sink


AgentTask  (record)  ──embeds──▶  Step  (per-step record)
   │ status: planning → executing → completed | failed | cancelled
   └─ Step.status: pending → running → done | failed | skipped
```

Restart-recovery edge (factual): on `AgentTaskStore` load, any `AgentTask.status == "executing"`
is forced to `failed` (`state.py:81-84`).

## 7. End-to-end delivery path (observed, concrete)

```
core/autonomy.py (calendar event)
      │
      ├─▶ AgendaQueue.push(AgendaItem)                      [agenda.json]
      │
      ├─▶ autonomy.peek_ready() → AgendaItem
      │        │
      │        ├─▶ workflows.trigger("calendar", ...)       [workflows.json, status=triggered]
      │        ├─▶ workflows.bind_intent(run.id, intent_id) [status=awaiting_delivery, attempts++]
      │        └─▶ AgendaQueue.consume(item.id)
      │
      └─▶ (later) workflows.complete_by_intent(intent.id)   [status=completed]
```

This is the only **full** cross-cluster path observed in the Recon. It shows the four state
machines (`AgendaItem` → `WorkflowRun` → `IntentRecord`) cooperating via string-id references,
with no shared "Workflow" orchestrator object mediating them.
