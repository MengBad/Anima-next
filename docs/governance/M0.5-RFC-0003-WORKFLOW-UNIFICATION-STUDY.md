## 1. Inventory

Every "workflow-like" concept observed in the Recon, described only.

### 1.1 Task-execution world (`anima/agent/`)

- **`OwnerAgent`** (`agent/owner_agent.py:22`) — orchestrator for the `!anima agent` handler;
  wires planner + executor + store + auditor; entry `submit`/`approve`/`cancel`/`status_text`.
- **`AgentTask`** (`agent/state.py:30`) — multi-step task record (`id, request, creator, status,
  steps[], current_step, context, error, timestamps`). Status: `planning → executing →
  completed|failed|cancelled`.
- **`Step`** (`agent/state.py:19`) — per-step record embedded in `AgentTask` (`index, description,
  tool_name, tool_args, status, result, error`). Status: `pending → running → done|failed|skipped`.
- **`AgentTaskStore`** (`agent/state.py:70`) — persistence root for `AgentTask`+`Step`
  (`data/agent_tasks.json`); dedup; restart recovery (`executing → failed`).
- **`TaskPlanner`** (`agent/planner.py:22`) — `plan(request, task) → list[Step]`; LLM decompose +
  deterministic keyword fallback (max 6 steps). Stateless.
- **`AgentExecutor`** (`agent/executor.py:33`) — `execute(task) → str`; per-step run + persist;
  `MAX_STEPS=20`, `MAX_TOOL_RETRIES=3`, `STEP_TIMEOUT=180`; cancel (`_cancel`); circuit-breaker.
- **`AgentAuditor`** (`agent/audit.py`) — emits `agent_progress` events.

### 1.2 Content-delivery world (`anima/core/`)

- **`WorkflowRun`** (`core/workflows.py:13`) — delivery record (`kind, source_id, target_group,
  content, event_key, id, status, intent_id, attempts`). Status: `triggered → awaiting_delivery →
  completed|cancelled|failed`.
- **`WorkflowStore`** (`core/workflows.py:37`) — persistence root for `WorkflowRun`
  (`data/workflows.json`); `trigger`/`bind_intent`/`complete_by_intent`/`cancel`/`fail_by_intent`.

### 1.3 Intent / delivery-queue world (`anima/core/`)

- **`IntentRecord`** (`core/intents.py:18`) — intent record (`kind, source, target, content,
  priority, not_before, expires, id, status, attempts`). Status: `queued → selected → dispatched →
  completed`; terminal `cancelled|expired|failed`.
- **`IntentLedger`** (`core/intents.py:47`) — persistence root for `IntentRecord`
  (`data/intent_ledger.json`); `create`/`claim`/`mark_dispatched`/`release`/`complete`/`expire`.

### 1.4 Agenda world (`anima/cognitive/`)

- **`AgendaItem`** (`cognitive/agenda.py`, carried by `AgendaQueue`) — scheduled autonomous item
  with `intent_id` reference.
- **`AgendaQueue`** (`cognitive/agenda.py:64`) — FIFO/priority hybrid persisted queue
  (`data/agenda.json`); `push`/`peek_ready`/`consume`/`cancel`.

### 1.5 Lifecycle / execution contracts (`anima/contracts/`)

- **`PipelineContext`** (`pipeline/context.py`, implements `PipelineContextProtocol`
  `contracts/pipeline.py:19`) — **Immutable** data carrier (ADR-0002).
- **`ExecutionContext`** (`constitution/execution.py`, implements `ExecutionContextProtocol`
  `contracts/execution.py:22`) — **Mutable** lifecycle carrier (ADR-0002); fields `trace_id,
  budget, cancellation, deadline, attempt, checkpoint`. **Unwired** in production.
- **`CancellationToken`** (`contracts/lifecycle.py:18`) — Protocol, **interface-only** (no ref impl).
- **`Deadline`** (`contracts/lifecycle.py:27`) — Protocol, **interface-only**.
- **`Checkpoint`** (`contracts/lifecycle.py:36`) — Protocol, **interface-only**; message-pipeline
  impl documented as missing (`contracts/execution.py:50`).
- **`ResourceBudget`** (`guardrails.py:111`, implements `ResourceBudgetProtocol
  contracts/lifecycle.py:45`) — the **only** lifecycle primitive with a reference implementation;
  consumed by `AgentExecutor`.

### 1.6 Constitution planning/execution (`anima/constitution/`, implemented, unwired)

- **`Plan`** (`constitution/state.py:188`) — canonical Plan shape (`task_graph`/`ordering`/
  `branching`/`rollback`/`status`); transient (RFC-0106).
- **`derive_plan`** (`constitution/planner.py:22`) — `p(goal, drive, context) → Plan`.
- **`execute_plan`** (`constitution/execution.py:34`) — `Plan → ExecutionResult` (read-only).
- **`ExecutionRuntime`** (`constitution/execution.py:67`) — infra carrier of the execution act;
  not a constitution authority.
- Observed production callers of all four: **none** in the Recon.

### 1.7 Reply-generation pipeline (`anima/pipeline/`)

- **`generation` stage** (`pipeline/stages/generation.py`) — produces reply text; includes
  `retry_messages` path and `_RETRY_PROMISE` handling; calls `ReActLoop.run` for tool-using replies.
- **`ReActLoop`** (`agent/react.py:26`) — ReAct tool-using loop (`max_rounds=5`).

### 1.8 Cross-cutting primitives (no single owner observed)

- **`Retry`** — scattered across ≥5 sites: `AgentExecutor` (`MAX_TOOL_RETRIES`), LLM handler
  (`retry_count`), channel (`onebot11` retry param), capability resolver (fallback chain),
  `IntentLedger.release` → `queued`.
- **`Queue`** — scattered across ≥3 sites: `AgendaQueue`, `IntentLedger` (queue semantics), channel
  backpressure.

## 2. Ownership

Per object: who owns, who writes, who consumes, where persisted, lifecycle. No judgment.

| Object | Owns (root) | Writes / mutates | Consumes (read) | Persists to | Lifecycle |
|---|---|---|---|---|---|
| `AgentTask` (+`Step`) | `AgentTaskStore` (`state.py:70`) | `AgentExecutor` (runtime), `OwnerAgent` (status/cancel), `AgentTaskStore` | `OwnerAgent`, `AgentExecutor` | `agent_tasks.json` | `planning→executing→completed\|failed\|cancelled` |
| `WorkflowRun` | `WorkflowStore` (`workflows.py:37`) | `WorkflowStore` (`trigger`/`bind_intent`/`complete_by_intent`/`cancel`/`fail_by_intent`) | `monitors/scheduler`, `core/autonomy`, `webui` | `workflows.json` | `triggered→awaiting_delivery→completed\|cancelled\|failed` |
| `IntentRecord` | `IntentLedger` (`intents.py:47`) | `IntentLedger` (`create`/`claim`/`mark_dispatched`/`release`/`complete`/`expire`) | `AnimaCore`, `WorkflowStore` (id ref) | `intent_ledger.json` | `queued→selected→dispatched→completed`; terminal `cancelled\|expired\|failed` |
| `AgendaItem` | `AgendaQueue` (`agenda.py:64`) | `AgendaQueue` (`push`/`consume`/`cancel`/`_prune_expired`) | `core/autonomy`, `llm/handler`, `webui` | `agenda.json` | `queued→consumed\|cancelled\|expired` |
| `PipelineContext` | pipeline runner (`anima.pipeline`) | pipeline stages (during run) | all pipeline stages | not persisted (in-memory) | per-message-turn |
| `ExecutionContext` | `ExecutionRuntime` (`constitution/execution.py:67`) | `ExecutionRuntime.run` (`budget`/`attempt`); `execute_plan` reads only | `execute_plan`, `ExecutionContextAdapter` | not persisted (observed) | per-run (unwired) |
| Constitution `Plan` | `Planner`/`derive_plan` (`constitution/planner.py`) | `derive_plan` (create); `revise` not in production | `execute_plan`, `ExecutionRuntime` | not persisted (transient, RFC-0106) | RFC-0002 lifecycle (draft→active→superseded/deprecated) |
| `ResourceBudget` | `guardrails.ResourceBudget` (`guardrails.py:111`) | `AgentExecutor` (`check_duration`/`consume_*`) | `AgentExecutor`, `ExecutionContextProtocol.budget` | in-memory (per run) | per-run |
| `CancellationToken` | **interface only** | — | `ExecutionContextProtocol.cancellation` | — | — |
| `Deadline` | **interface only** | — | `ExecutionContextProtocol.deadline` | — | — |
| `Checkpoint` | **interface only** | — | `ExecutionContextProtocol.checkpoint` | — | — |

Factual summary (no conclusion): each of the **4 persisted state machines** has its **own store
+ owner** (`AgentTaskStore`, `WorkflowStore`, `IntentLedger`, `AgendaQueue`). No shared owner.
`AgentExecutor` is the sole runtime mutator of `AgentTask`. The two context protocols are owned by
different layers and split Immutable/Mutable by ADR-0002. 3 of 4 lifecycle primitives have no
implementation. The constitution `Plan`/`ExecutionContext` are owned inside the constitution
package and are **not on the production mutation path**.

## 3. Relationship

Described only. No "should". Arrows are observed references/calls, not proposed structure.

```
AgentTask  ──embeds──▶  Step
OwnerAgent  ──owns──▶  AgentTaskStore  ──persists──▶  agent_tasks.json
OwnerAgent  ──drives──▶  AgentExecutor.execute(task)
AgentExecutor  ──calls──▶  TaskPlanner.plan(request, task)  ──▶  LLM / keyword fallback  ──▶  list[Step]
AgentExecutor  ──writes──▶  AgentTaskStore.save()  ──▶  AgentTask + Step
AgentExecutor  ──emits──▶  AgentAuditor.emit("agent_progress")


WorkflowRun  ──references (string id)──▶  IntentRecord.id
WorkflowStore  ──persists──▶  workflows.json
WorkflowStore  ──owned by──▶  AnimaCore
IntentLedger  ──persists──▶  intent_ledger.json
IntentLedger  ──owned by──▶  AnimaCore
AgendaItem  ──carries──▶  intent_id  ──(bound into)──▶  WorkflowRun  (via autonomy.py:440)
AgendaQueue  ──persists──▶  agenda.json
AgendaQueue  ──owned by──▶  AnimaCore


PipelineContext  ──implements──▶  PipelineContextProtocol  (Immutable)
ExecutionContext  ──implements──▶  ExecutionContextProtocol  (Mutable)
ExecutionContextProtocol.budget        ──▶  ResourceBudgetProtocol
ExecutionContextProtocol.cancellation  ──▶  CancellationToken   (interface only)
ExecutionContextProtocol.deadline      ──▶  Deadline            (interface only)
ExecutionContextProtocol.checkpoint    ──▶  Checkpoint          (interface only)
ADR-0002: the two contexts are deliberately split (Immutable data vs Mutable lifecycle)


derive_plan(Goal, Drive, Context)  ──▶  Plan  (constitution/state.py:188)
Plan  ──▶  execute_plan(Plan, ExecutionContext)  ──▶  ExecutionResult
ExecutionRuntime.run  ──wraps──▶  execute_plan
Observed production callers of derive_plan / execute_plan / ExecutionRuntime: none.


Retry  ──appears in──▶  AgentExecutor, LLM handler, channel (onebot11), capability resolver, IntentLedger.release
Queue  ──appears in──▶  AgendaQueue, IntentLedger, channel backpressure
(neither "Retry" nor "Queue" is observed to have a single owning component)
```

End-to-end delivery path (the only full cross-cluster path observed):

```
core/autonomy.py (calendar event)
   ├─▶ AgendaQueue.push(AgendaItem)
   ├─▶ autonomy.peek_ready() → AgendaItem
   │      ├─▶ workflows.trigger("calendar")         [WorkflowRun, status=triggered]
   │      ├─▶ workflows.bind_intent(run.id, intent_id)  [status=awaiting_delivery, attempts++]
   │      └─▶ AgendaQueue.consume(item.id)
   └─▶ (later) workflows.complete_by_intent(intent.id)  [status=completed]
```

This path shows `AgendaItem → WorkflowRun → IntentRecord` cooperating via **string-id references**,
with **no shared "Workflow" orchestrator object** mediating them.

## 5. Questions

Only questions that require a **governance ruling** are listed here. All are asked, none answered.
Implementation-detail questions (e.g. *will the constitution `Plan` ever reach production?* — Recon
Q6) are excluded as design-level, resolvable inside RFC-0003 once scope is set. Full wording of the
underlying Recon findings is in `WORKFLOW-OPEN-QUESTIONS.md`.

**GQ1 — What is the canonical "Workflow"?**
The Recon found **four independent persisted state machines** that each look workflow-like
(`AgentTask`, `WorkflowRun`, `IntentRecord`, `AgendaItem`). Are they one "Workflow" concept with
four facets, or four distinct concerns (task-execution / content-delivery / intent-dispatch /
autonomous-agenda)? If one canonical object is expected, which of the four is it?

**GQ2 — Does RFC-0003 "Workflow" include the content-delivery ledger?**
`WorkflowRun`/`WorkflowStore` is a **content-delivery** ledger (trigger → delivery intent → result),
wired into `monitors/scheduler` and `core/autonomy` — not a task-execution graph. Is it inside
RFC-0003's "Workflow" scope, or is RFC-0003 limited to task-execution orchestration?

**GQ3 — Are `WorkflowRun` and `AgentTask` at the same layer?**
Both persist multi-step activity. One is delivery-centric, the other execution-centric. Are they
peers (two Workflow flavors), or is one a sub-concept of the other?

**GQ4 — Does `Checkpoint` (resume) belong to Workflow or Execution?**
`Checkpoint` is an interface-only Protocol; `AgentTask.current_step` already provides step-level
resume. Is "resume" a Workflow-layer, Execution-layer, or neither responsibility? Should it unify
with `current_step` or stay separate?

**GQ5 — Does `Retry` belong to Workflow?**
Retry is scattered across ≥5 sites with no single owner. Is it a Workflow responsibility, or a
cross-cutting concern owned per-layer? If Workflow owns it, which sites delegate?

**GQ6 — Does `Queue` belong to Workflow?**
Queues appear at ≥3 independent sites (`AgendaQueue`, `IntentLedger`, channel backpressure). Is
"queue" part of Workflow, or are these independent queues? Should RFC-0003 define one queue
abstraction or acknowledge several?

**GQ7 — Is the Workflow/run-state lifecycle independent of the Plan lifecycle?**
RFC-0002 owns the `Plan` lifecycle (draft→active→superseded/deprecated). The observed run states
(`AgentTask`, `WorkflowRun`, `IntentRecord`) are separate. Is the run-state lifecycle **independent**
of the Plan lifecycle, or coupled to it? Who owns run-state transitions?

**GQ8 — What is the canonical classification of `AgentTask`+`Step`?**
RFC-0002 explicitly **deferred** this (§8 / §10 Q6): are `AgentTask`+`Step` the RFC-0002 `Plan`, the
RFC-0003 run-state, or a hybrid? If run-state, what is the relationship between `AgentTask.steps`
and the RFC-0002 `Plan.task_graph`? This is carried over from RFC-0002 and is a governance
classification, not an implementation detail.

**GQ9 — Who owns run activation / hand-off authority?**
RFC-0002 names **Planning Authority** as the sole `Plan` activator. The observed production paths
hand off differently: `OwnerAgent.submit → AgentExecutor.execute` (permission-gated, immediate);
`WorkflowRun` moves `triggered → awaiting_delivery` via `bind_intent` (no named activation
authority). Is there one run-activator across task-execution and content-delivery, or are they
separate (OwnerAgent vs WorkflowStore)?

**GQ10 — Do the missing lifecycle primitives belong to Workflow or Execution?**
`CancellationToken` / `Deadline` / `Checkpoint` are Protocols with no reference implementation
(except `ResourceBudget`). Are they Workflow primitives, Execution primitives, or shared
infrastructure? (Overlaps GQ4.)
