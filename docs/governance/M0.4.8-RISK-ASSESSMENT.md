## Narrative

**R1 / R4 (authorization):** The D-A1 two-level gate + fail-closed allowlist is the primary
control. A non-cohort caller hitting `code_execute` is denied at `call_capability` with a
`capability_route_denied` audit event — no silent exposure. R6 schema gate ensures the LLM
never even sees the schema for a non-permitted principal, preventing deny-loop noise.

**R2 / R3 (routing):** If routing misbehaves, the D-A4 `failed` / `routed` counters surface it
immediately. Because activation is config-only and reversible, the fastest mitigation is the
§6 rollback (flip flag + restart).

**R7 (scope creep):** The highest-severity risk is accidental F2 entry. The RFC §7 gate +
manual allowlist review keeps `code.execute` execution OUT until a separate, explicit ruling.

**R9 (boundary crossing):** Pilot A's objective is *governance, not execution* (RFC §1), so the
`allowed → routed → executed` transition is **not** a success signal — it is a stop criterion.
Because no code-level halt exists between `routed` and the provider call
(`tools/__init__.py:326-328`), and because inserting one would be a code change (forbidden in
M0.4.8), the boundary is held by three non-code controls: observation-only protocol, the
`allowed/routed > 0` tripwire, and a ≤ 3-principal blast-radius cap. Residual risk is low: an
accidental invocation lands on the pre-existing hardened `run_python` base, i.e. the Pilot
creates **no exposure that did not already exist** — it only makes a governed route reachable to
a named cohort.

**Why no validation coverage is lost:** the positive predicate
`pilot_capability_permitted(caller)` is shared by the schema gate and the route gate
(`tools/__init__.py:290` / `:318`, defined at `:188`). Observing it at the schema gate proves identity resolution
with zero execution risk (RFC §8 C3). Provider-level behavior is deferred to Pilot B (RFC §9),
where it belongs.

---

## Conclusion

All identified risks are mitigable with the existing M0.4.7 controls (gate + allowlist + schema
gate + telemetry + controlled restart). No new code is required to operate or roll back the Pilot.
Provider execution is **out of scope by definition**, not by limitation — it is deferred to
Pilot B behind the F2 decision gate (RFC §7 / §9).
