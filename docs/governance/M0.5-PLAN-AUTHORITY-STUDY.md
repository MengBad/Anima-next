## 0. The single question

> **Who owns the canonical definition of Plan?**

Three candidate authorities exist in the current codebase and governance state. Each is described on five axes — **ownership**, **invariants**, **compatibility**, **migration impact**, **documents affected** — using only observed facts from `M0.5-PLANNING-RECON-REPORT.md` and `M0.5-PLAN-UNIFICATION-STUDY.md`. No preference is expressed. No new authority is proposed.

---

## Authority 1 — Digital-Life Ontology Planning Authority (RFC-0106)

### Ownership
The **digital-life ontology track** (010x series). Per RFC-0106 §6, the **Planning Authority** is the sole constructor of Plan (single-writer rule O1). RFC-0106 is **Anchored / Frozen** (Foundation Validation #6); modifiable only via Foundation Evolution F1–F4.

### Invariants (as defined by RFC-0106)
- `Plan = p(Goal, Drive, Context)` — Transient-Derived, **not Owned** (§4 P1).
- Constructed (not restored) each time; discarded after Execution consumes it (§5.4 V5).
- The **Execution Authority** consumes Plan but does not construct or mutate it (§8 E4).
- Structure dimensions: task graph / ordering / branching / rollback (§4.1; branching/rollback are the reserved Workflow interface points).

### Compatibility
- **With P1** (constitution `Plan`, `state.py:188`): aligned — P1 models P3's shape and is also transient.
- **With P2** (production `AgentTask.steps`, `agent/state.py:20-40`): conflict — P2 is constructed by `TaskPlanner` with no declared relationship to this authority, and P2 carries an Owned-style lifecycle, which this authority's contract does not grant.

### Migration impact
If RFC-0002 adopts this authority, the Draft writes **against the frozen ontology**. Staying within RFC-0106's stated contract requires **no Foundation change**. Any deviation from that contract (e.g., granting Plan a lifecycle or a store) requires **Foundation Evolution F1–F4** to amend RFC-0106 before it can be ratified.

### Documents affected
- `docs/rfc/RFC-0002-Planning.md` (future) — must cross-reference RFC-0106 and stay within its contract.
- `docs/rfc/RFC-0106-Plan.md` — touched **only** if F1–F4 is invoked.

## Authority 2 — Infrastructure Planning Authority (to be defined by RFC-0002)

### Ownership
A **new Planning Authority established by the 000x infrastructure series** (RFC-0002), distinct from the digital-life ontology's Planning Authority. Currently **undefined** — RFC-0002 would establish it. This is the "separate infra Planner" path of Decision A.

### Invariants
**Not yet defined.** RFC-0002 would set them. (This study does not predefine them.)

### Compatibility
Exists **in parallel** to Authority 1 (RFC-0106). The M0.5 Roadmap (r1, frozen) already separates the 000x infra track from the 010x ontology track and placed the Planning Interface inside RFC-0002. Does **not** modify RFC-0106. Its relationship to P2 (production) is established by RFC-0002.

### Migration impact
**No Foundation change.** RFC-0002 declares a separate infra-track Planning Authority and an explicit track-separation statement. RFC-0106 / RFC-0107 remain untouched. If, during the Draft, RFC-0002 discovers it must alter the frozen ontology, it annotates "Requires Foundation Evolution (F1/F2)" and awaits that decision — drafting is not blocked.

### Documents affected
- `docs/rfc/RFC-0002-Planning.md` (future) — declares the new authority + track separation.
- `docs/governance/M0.5-ROADMAP.md` — already reflects the 000x / 010x separation; no change needed.
- No Foundation document modified.

## Authority 3 — Production runtime (de facto, undeclared)

### Ownership
**No declared Planning Authority.** The canonical Plan definition is currently owned **de facto** by production components: `TaskPlanner` (`agent/planner.py:22`) constructs; `AgentExecutor` (`agent/executor.py:33`), `OwnerTaskAgent` (`core/tasks.py:122`), `agent_tools`, `owner_agent` drive it. Ownership is diffuse across the production runtime — no single authority is named.

### Invariants
**None declared.** De facto behavior: Plan-as-steps is produced by an LLM-driven flat decomposition and is driven by the production executors. This is the object P2 in the Study.

### Compatibility
**Conflicts with Authority 1** (RFC-0106 §6 assigns construction solely to the Planning Authority and defines Plan as Transient-Derived with no lifecycle). P2 is the production object this authority governs; it does not carry the ontology's stated contract.

### Migration impact
Legitimizing this authority as canonical requires **overriding RFC-0106's Planning Authority claim → Foundation Evolution F1–F4** to amend RFC-0106. Alternatively, RFC-0002 could explicitly reclassify P2 as a distinct concept from Plan — but that reclassification is a separate question (out of scope per ruling). Under either path, making Authority 3 canonical touches the frozen ontology unless RFC-0002 instead declares it a non-Plan record.

### Documents affected
- `docs/rfc/RFC-0002-Planning.md` (future) — adopts P2 as canonical, or reclassifies it.
- `docs/rfc/RFC-0106-Plan.md` — amended via F1–F4 **if** P3 is overridden.
