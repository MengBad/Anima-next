# M0.4.8 Decision Matrix

Three governance choices for the approver. Companion to `GOVERNANCE_DECISION.md`.

| Dimension | **Option A — Approve Pilot A (config-only)** | **Option B — Keep `capability_mode = OFF` indefinitely** | **Option C — Reject Pilot A & reopen RFC** |
|---|---|---|---|
| **What happens** | YAML flip `capability_mode=True` for a named ≤3-principal cohort; controlled restart; observe-only window. No code. | Nothing. M0.4.7 stays a dormant, validated capability. | RFC returned for rework; Pilot cancelled. |
| **Benefits** | Validates the full governance chain (schema→routing→identity→allowlist→telemetry) on real traffic with zero code change. Proves the gate works. Sets a precedent for controlled capability rollout. | Zero risk, zero change, zero operational load. Cleanest conservative posture. | Forces re-examination; a genuinely better design *could* emerge. |
| **Risks** | Boundary crossing is detective-only (tripwire fires after crossing, `:326-328`); operator YAML error; blast radius if cohort mis-scoped. All mitigable, none require code. | Capability layer never exercised on real load; config-wiring mistakes stay undetected; M0.4.7 investment unexercised. | Document churn with no new information (review found only Clarify, no defect); likely reconverges on same design; signals the review wasn't trusted. |
| **Operational cost** | Low: one YAML edit + one controlled restart + a bounded monitoring window + one named observer. | None. | Medium: another design + review cycle. |
| **Rollback complexity** | Low: flip `capability_mode=False` + restart. Tripwire already demonstrates fail-closed. Reversible in minutes. | N/A (nothing activated). | N/A (nothing activated). |
| **Governance impact** | Positive: demonstrates the review→approve→pilot discipline works end-to-end; establishes a repeatable controlled-activation pattern. | Neutral / conservative: safe, but leaves a validated capability permanently unproven; defers the same decision to a later date. | Negative if avoidable: weakens the "review outcome is sufficient" signal; adds latency without new evidence. |

## Bottom line

- **A** is the lowest-cost way to *prove* the M0.4.7 gate works on real traffic, with
  containment built in.
- **B** is the safest but leaves the investment unexercised and only postpones this exact
  decision.
- **C** is not justified by the review record (no Reject / no defect).

See `GOVERNANCE_DECISION.md` §6 for the recommendation.
