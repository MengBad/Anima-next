## 5. Key safeguards (for the approver)

- **Default OFF** — `capability_mode=False` until the authorized operator flips it under the
  Approval Record. The `capability_mode` gate (`tools/__init__.py:314-315`) is the real prevention.
- **Detection, not prevention** — the telemetry tripwire detects a boundary crossing *after* it
  occurs and triggers rollback; it is **not** a code-level block (F-02).
- **Blast radius** — ≤ 3 named principals on the pre-existing hardened `run_python` base; no new
  exposure is created (F-11).
- **No execution validated** — Pilot A stops before `provider.execute()`; execution is deferred to
  Pilot B behind the F2 gate (RFC §7 / §9).
- **Reversible** — kill switch = revert YAML + controlled restart.

## 6. What approval does NOT authorize

- No **F2** (code-execution permission) — still gated (RFC §7).
- No **sandbox** / resource-isolation changes.
- No **production rollout**.
- No new code, no new capability, no new RFC.

Authorized operator performs the Activation Procedure (RFC §12.4): sign Approval Record → edit
YAML → controlled restart → reviewer confirms telemetry. Pilot runs its observation window, then
closes per RFC §11. The Agent does **not** flip the flag autonomously.
