## 1. Contract → production gap (precise)

### 1.1 `Plan` dataclass — `anima/constitution/state.py:188`
Current fields: `goal_target, task_graph, ordering, branching, rollback, context_ref, emphasis, focus`.
Missing vs §5 contract: **`id`, `contract_version` (1.0.0), `goal_ref`, `source` (enum), `status`, `created_at`**. (`goal_target` is narrower than §5 `goal_ref`.)
→ **Action:** extend `Plan` to the full §5 contract. Keep `derive_plan` pure.

### 1.2 Planning Interface — `anima/constitution/planner.py` `Planner`
Current ops: `adopt_goal`, `build_plan`, `cancel_plan`, `active_plan` (prop).
RFC-0002 §6 ops: `request_plan`, `activate_plan`, `read_plan`, `revise_plan`, `list_plans`, `invalidate_plan`.
Mapping:
- `build_plan` ≈ `request_plan` (rename + emit `draft` state + assign `id`/`contract_version`) — name differs, no `id`/`status` today.
- `cancel_plan` = drop-only (no `deprecated` state, no `reason`) — NOT `invalidate_plan`.
- **Missing entirely:** `activate_plan`, `read_plan`, `revise_plan` (supersede effect), `list_plans`, `invalidate_plan`.
→ **Action:** realize the full `PlanningInterface` with exact op names; single-writer guard.

### 1.3 Transient Plan registry
Current: `Planner._active_plan` holds exactly **one** Plan (no history, no per-Goal index).
RFC-0002 needs: multiple Plans per Goal, `superseded` history, `list_plans(goal_ref)`.
→ **Action:** add an in-memory (non-persisted) `PlanRegistry` keyed by `plan_id`, indexed by `goal_ref`. Still transient (§8 — never written to disk).

### 1.4 Runtime wiring — `anima/agent/planner.py` `TaskPlanner`
Current: `TaskPlanner.plan(request) -> list[Step]` (LLM + heuristic). Not a `Plan`; no lifecycle; no `source=planner`.
RFC-0002: `Plan` with `source=planner` produced via `PlanningInterface.request_plan`; Workflow consumes the `active` Plan.
→ **Decision D1 (pending — Phase B-2, NOT a gate blocker):** how `TaskPlanner` relates to `derive_plan`. Options (agent recommendation notes in Appendix A; none pre-approved):
  - (a) `TaskPlanner` becomes the LLM decomposition *backend* inside `derive_plan` — `derive_plan` calls `TaskPlanner._decompose` to build `task_graph`; `PlanningInterface` owns lifecycle.
  - (b) Keep `TaskPlanner` as the execution step-list and have `AgentExecutor` call `PlanningInterface.request_plan` (which internally uses `derive_plan` → `TaskPlanner`) to produce the canonical Plan.

### 1.5 Lifecycle state machine + guards
Current: `Planner` has no `status` field, no transitions, no transition guard.
RFC-0002 §7/§7.1: `draft → active` (`activate_plan`, Authority only); `active →` (consumed→discarded | `superseded` via `revise_plan` | `deprecated` via `invalidate_plan`). Execution/Memory MUST NOT transition.
→ **Action:** implement `status` enum + transition table inside `PlanningInterface`; reuse `invariants.assert_no_cross_authority_mutation` pattern; add an explicit "only `PlanningInterface` may set `Plan.status`" guard.

## 2. Implementation slices (ordered by dependency)

### S1 — Plan contract upgrade (`state.py`)
Extend `Plan` dataclass to §5: `id` (uuid), `contract_version="1.0.0"`, `goal_ref` (string), `source` (enum: `planner|human|memory|external_api`, default `planner`), `status` (enum: `draft|active|superseded|deprecated`, default `draft`), `created_at`. Add a `Task` dataclass (§5: `id, title, intent, capability_need?, depends_on, estimates`) — currently the constitution uses bare dicts; a `Task` dataclass gives contract fidelity and enables `capability_need` routing later. `derive_plan` must populate all new fields (defaulted where derivable). Smoke test: construct a `Plan` with every §5 field present.
- **Depends on:** none. **Gate:** M0.4.x.

### S2 — PlanningInterface realization (`planner.py`)
Rename `build_plan` → `request_plan` (emit `draft` Plan with `id`+`contract_version`+`status=draft`); add `activate_plan` (`draft→active`), `read_plan`, `revise_plan` (emit fresh Plan, mark old `superseded`), `list_plans(goal_ref)`, `invalidate_plan` (→`deprecated`, no replacement). Add transient `PlanRegistry`. Single-writer guard on `Plan.status`. Smoke tests per op (mirrors M1 smoke discipline).
- **Depends on:** S1.

### S3 — decompose backend wiring (`derive_plan` + `TaskPlanner`)
Per D1(a): inject `TaskPlanner` (LLM decomposer) into `derive_plan` so `task_graph` is produced from a real request instead of the hardcoded `t1/t2/t3`. Keep `derive_plan` pure & deterministic given fixed decomposer + inputs. This is the point where the LLM actually enters Plan production.
- **Depends on:** S1, S2 (interface exists); `TaskPlanner` importable.

### S4 — Runtime wiring (`anima/agent` layer)
`AgentExecutor` / `OwnerAgent` call `PlanningInterface.request_plan(goal, context)` → `activate_plan` → iterate the `active` Plan's `task_graph`. (Workflow consumption is RFC-0003; until then the executor consumes the Plan structure directly.) Replaces the current `TaskPlanner.plan()` call site.
- **Depends on:** S2, S3.

### S5 — Cross-authority guards & regression (`invariants` + tests)
Ensure Execution/Memory cannot transition a Plan (reuse `invariants`). Add regression tests that `execution.revise_plan(...)` / `reflection.save_plan(...)` are rejected (RFC-0002 E6, O1).
- **Depends on:** S2.
