## 1. Current Production Inventory

Modules currently involved in Planning. **Descriptive only** — no judgement, no recommendation.

### 1.1 `anima/constitution/planner.py` — Constitution Planner (UNWIRED)
- `derive_plan(goal, drive, context)` (`:22`): pure `p(Goal, Drive, Context)` derivation — same inputs ⇒ same `Plan`, no side effects, reads upstreams read-only.
- `class Planner` (`:78`): lifecycle owner that *constructs* and *cancels* Plans for the active Goal; single-writer (O1); never mutates Goal/Drive/Context.
- Exposes: `adopt_goal()` (`:92`), `build_plan()` (`:100`), `cancel_plan()` (`:108`), `active_plan` property (`:114`).
- **Wiring:** imported only inside `constitution/` and by `tests/test_constitution_m1.py`; **not referenced** by `anima_core.py`, `pipeline/`, or `agent/`.

### 1.2 `anima/constitution/state.py` — Constitution State (UNWIRED)
- `class Plan` dataclass (`:188`): documented **Transient-Derived, never stored** (RFC-0106 §4). Fields: `goal_target`, `task_graph`, `ordering`, `branching`, `rollback`, `context_ref`, `emphasis`, `focus`.
- **No lifecycle field**; only `Goal` has a `GoalLifecycle`. Plan carries no `id`, `status`, `contract_version`, or `goal_ref`.

### 1.3 `anima/agent/planner.py` — Runtime TaskPlanner (WIRED)
- `class TaskPlanner` (`:22`): decomposes a natural-language request into an **ordered `list[Step]`** via LLM (`plan()` `:26`), with deterministic keyword fallback `_fallback()` (`:64`).
- **Wired into:** `AgentExecutor` (`:22,43,89`), `OwnerAgent` (`:16,33`), `anima_core.py:54-55`.
- Contract fit: does **not** implement RFC-0002 — no `Plan` object, no Planning Authority, no lifecycle, no `activate`/`revise`/`invalidate`.

### 1.4 `anima/core/workflows.py` — QQ Delivery Ledger (WIRED, persisted)
- `class WorkflowRun` (`:13`): outbound-message delivery tracking (kind/source_id/target_group/content/status/…). States: `triggered | awaiting_delivery | completed | cancelled | failed`.
- Purpose: **delivery tracking**, not a general run engine. (RFC-0003 territory; listed for dependency awareness only.)

### 1.5 `anima/agent/state.py` — Agent Multi-step Tasks (WIRED, persisted)
- `Step` (`:19`) / `AgentTask` (`:30`): agent step-list + task state (`planning | executing | completed | failed | cancelled`). `AgentTaskStore` persists `agent_tasks.json`.
- Run-lifecycle in `AgentExecutor` (`:33`): `execute()`/`request_cancel()`/retry/timeout/budget/circuit-breaker. **No** suspend/resume/abort/report_task_outcome.

### 1.6 `anima/core/tasks.py` — Owner Engineering Queue (WIRED, persisted)
- `class Task` (`:14`): owner task queue (`planned | running | awaiting_approval | completed | failed | cancelled | rejected`). Owned via `anima_core.py:49-52`.

### 1.7 Persistence layer
- Three independent JSON stores exist (`workflows.json`, `agent_tasks.json`, `owner_tasks.json`). **No store** for an RFC-0002 `Plan` (by design — Plan is never stored; see §7 persistence boundary).

## 3. Implementation Slices

Five slices in dependency order. **Each slice lists Scope / Inputs / Outputs / Dependencies only — no method, no decision.**

### Slice 1 — Plan data-contract completion
- **Scope:** Extend `constitution.Plan` dataclass to carry the RFC-0002 §5 fields (identity + runtime state) while preserving backward compatibility with the existing `derive_plan` return shape.
- **Inputs:** RFC-0002 §5 field definitions; RFC-0002 §7 runtime-state definitions; existing `Plan` fields (RFC-0106).
- **Outputs:** Extended `Plan` dataclass (new fields added; existing fields unchanged).
- **Dependencies:** RFC-0106 frozen (satisfied); M0.4.x gate READY (satisfied).

### Slice 2 — Planning Interface implementation
- **Scope:** Add the RFC-0002 §6 interface operations to the Planning Authority owner, plus an in-memory plan registry, honoring the single-writer rule (O1) and the cross-authority mutation guard.
- **Inputs:** RFC-0002 §6 semantic interface; §7.1 transition ownership; `invariants.assert_no_cross_authority_mutation`.
- **Outputs:** `Planner` with lifecycle operations + in-memory `PlanRegistry`; single-writer enforced.
- **Dependencies:** Slice 1 (Plan fields ready).

### Slice 3 — `derive_plan` as the canonical Plan constructor (wiring)
- **Scope:** Establish `derive_plan` as the single `p`-derivation constructor feeding the RFC-0002 `Plan`; connect the existing LLM decomposition capability as a backend candidate for task-graph construction.
- **Inputs:** `constitution.derive_plan` (pure function, implemented); `agent.TaskPlanner._decompose` (LLM backend, implemented); RFC-0002 §4/§5.
- **Outputs:** A wired construction path from request → RFC-0002 `Plan`.
- **Dependencies:** Slice 1, Slice 2.
- *Note: the concrete integration shape (e.g. how `TaskPlanner` relates to `derive_plan`) is an implementation decision (D1) deferred to the implementation phase — not decided here.*

### Slice 4 — Runtime wiring
- **Scope:** Connect the Planning Interface into the live agent call sites that currently use `TaskPlanner.plan()`, so runtime produces an RFC-0002 `Plan`.
- **Inputs:** Existing runtime call sites (`AgentExecutor:22,43,89`; `OwnerAgent:16,33`; `anima_core.py:54-55`); Planning Interface (Slice 2/3 output).
- **Outputs:** Runtime path that obtains a compliant `Plan` via the Planning Interface.
- **Dependencies:** Slice 3.
- *Note: whether `TaskPlanner` is replaced or adapted, and the `Task` representation (D2), are implementation decisions deferred to the implementation phase — not decided here.*

### Slice 5 — Cross-authority guard + regression suite

## 4. Risks

Descriptive only — no mitigation decision, no solution.

- **R1 — Runtime compatibility.** `TaskPlanner.plan()` currently returns `list[Step]`; RFC-0002 `Plan` is a different structure. Wiring may break the existing return-type / field-access contracts at `AgentExecutor` / `OwnerAgent` / `anima_core` call sites.
- **R2 — Transient vs lifecycle tension.** Plan is **Transient-Derived, never stored** (RFC-0106 P1/P3), yet RFC-0002 §7 introduces runtime states (`draft → active → superseded → deprecated`). The boundary between "never persisted" and "governable runtime state" (RFC-0002 §8 persistence boundary) must be made explicit in code to avoid accidental persistence or lost resumability.
- **R3 — Authority boundary.** Planning Authority is single-writer and must never mutate upstream Goal/Drive/Context (guarded by `invariants`). Runtime wiring must not let callers bypass the guard.
- **R4 — Planner ownership at runtime.** `constitution.Planner` is UNWIRED; the live agent has no Planning Authority today. Establishing *who* holds the active Plan and *who* triggers transitions at runtime is unresolved.
- **R5 — Single vs multi Plan.** `Planner._active_plan` holds exactly one Plan; RFC-0002 implies a `PlanRegistry` (multiple Plans). The single/multi semantic must be reconciled.
- **R6 — Test-coverage gap.** `derive_plan` is covered by `test_constitution_m1`; lifecycle operations, the interface, and runtime wiring have **no** existing tests and must be built.
