# M0.5 Planning Recon Report

**Status:** Reconnaissance only — describes current code state and gaps. **NOT an RFC. NOT a design. No code change.**
**Branch:** `m0.5-roadmap`
**Scope of this report:** Identify what Planning / Workflow capability *already exists* in `anima/` so RFC-0002 (Planning) and RFC-0003 (Workflow) do not reinvent it. Read-only; no proposal, no RFC text, no code.
**Author:** Anima engineering (recon for governance review)

---

## 1. Executive summary

The codebase is **not barren** — it contains real, partly mature Planning and Workflow code. But it is **fragmented across three disconnected "worlds"** and carries **significant duplication**. The single most important takeaway for RFC-0002:

> There are already **three competing definitions of "Plan"** — and a **frozen ontology RFC (RFC-0106)** that already owns the word. RFC-0002 must resolve *which* "Plan" it standardizes before it writes a single line.

Two mature, non-redundant assets are worth building on directly:
- **`AgentExecutor`** (`anima/agent/executor.py:33`) — the only real execution engine (retry + backoff + timeout + circuit-break + per-step persistence). → belongs to RFC-0003.
- **`IntentLedger`** (`anima/core/intents.py:47`) — the only规范 state machine with validated transitions + persistence. → reusable substrate.

Everything Planning-shaped today is either a **hardcoded stub** (constitution `derive_plan`) or a **flat list with no structure** (production `TaskPlanner`). The richest *shape* and the real *content* live in two different, disconnected modules.

## 3. Three disconnected worlds

| World | Location | Nature | Wired into production? |
|---|---|---|---|
| **A. Constitution layer** | `anima/constitution/` | Pure-function contracts, M1.1–M1.11, anchored via RFC-0100~0111 | **No** — zero references from production code (only self + `tests/`) |
| **B. Production runtime** | `anima/agent/` + `anima/core/` | The real multi-step agent running on the QQ bot | **Yes** — assembled in `AnimaCore.__init__` |
| **C. Frozen ABI** | `anima/contracts/` | M0.1 protocol-only interfaces | Partial — adapters exist, `Checkpoint` has **no implementation** |

World A defines a clean `Plan`/`ExecutionContext` shape but is **never executed**. World B executes but with **ad-hoc shapes**. World C defines the lifecycle ABI but is **mostly unimplemented**. RFC-0002/0003 will have to pick a world to standardize against.

## 4. Planning-capable code (decides WHAT)

### 4.1 `derive_plan` — constitution-layer planner (M1.6)
**`anima/constitution/planner.py:22`** — `derive_plan(goal, drive, context) -> Plan`
- Returns a `Plan` dataclass with `task_graph` (3 hardcoded nodes: read→synthesize→present), `ordering`, `branching`, `rollback`.
- **The decomposition is content-independent**: every goal yields the same read→synthesize→present template (`:35-47`). Docstring self-labels "Heuristic (M1)".
- Pure function, guarded by `invariants.assert_no_cross_authority_mutation`.
- **Maturity: early prototype / deliberate placeholder.** Rich *shape*, fake *content*.

### 4.2 `TaskPlanner` — production planner
**`anima/agent/planner.py:22`** — `plan(request, task) -> list[Step]`
- LLM-driven decomposition (`_decompose`, `_SYSTEM_PROMPT` asks for 2–6 ordered steps), silent fallback to keyword heuristic (`:64-87`).
- Produces a **flat ordered `list[Step]`** — **no dependency graph, no branching, no per-step tool binding** (`tool_name` left empty for ReAct to decide at runtime, `state.py:22`).
- **Maturity: usable but shallow.** Real *content*, no *shape*.

### 4.3 `is_agent_task` — goal admission
**`anima/agent/intent.py:22`** — regex + `permission_level < LEVEL_OWNER` gate. Called at `llm/handler.py:1093`.
- **Maturity: mature but crude (regex).** Classification: **Planning (admission/routing).**

### 4.4 `IntentGenerator` — DEAD / broken code ⚠️
**`anima/cognitive/intent_generator.py:20`** — LLM intent generator.
- `:39` is missing `await` on an async `self.llm.chat_structured(...)`; the coroutine is then `.get()`-ed at `:45` → always `AttributeError` → swallowed by `:48` → **always returns `{"intent_type": "silence"}`**.
- Zero references outside its own file.
- **Maturity: stub / broken dead code.** Should be deleted, not extended.

### 4.5 `ControlledIteration` — mixed Planning + Workflow
**`anima/cognitive/controlled_iteration.py`** (825 lines) — scans quality → opens tickets (Planning) → picks candidate (Planning) → hard-coded staged patch pipeline with human approval gate + real rollback (`_restore_backup` `:733`, `_run_pytest` `:715`).
- **Maturity: mature but a hardcoded specialty flow**, not a reusable engine. The only real rollback in the repo.

**Planning classification summary:** two real planners exist (4.1, 4.2) with complementary strengths and zero shared interface; one is dead (4.4); admission is regex-based (4.3).

## 5. Workflow-capable code (runs HOW)

### 5.1 `execute_plan` — constitution-layer execution (M1.7)
**`anima/constitution/execution.py:34`** — `execute_plan(plan, context) -> ExecutionResult`
- **Does not dispatch anything.** Only counts `ordering` length and builds a description string. Docstring: "carrying is simulated for M1.7"; "scheduler / tool-executor / retry policy are explicitly NOT in scope (RFC-0107 NG1)".
- `branching`/`rollback` are only *printed* (`:52`,`:54`), never interpreted. `ExecutionStatus.PENDING/RUNNING/PARTIAL` are never produced.
- **Maturity: stub / boundary proof, not an implementation.**

### 5.2 `AgentExecutor` — the real execution engine ★
**`anima/agent/executor.py:33`** — `execute(task)`
- `MAX_STEPS=20`, `MAX_TOOL_RETRIES=3`, `STEP_TIMEOUT=180`; lazy-plan if no steps; **resume from `task.current_step`** (`:98`); per-step `running`→persist→`wait_for(timeout)`; three failure branches (timeout / resource / step-fail); **exponential backoff `min(2**attempt, 8)`** (`:196`); circuit-break after 3 consecutive failures (`:157-163`); per-step disk persistence.
- **Maturity: mature — the only real execution engine in the repo.** → RFC-0003 asset.

### 5.3 `ReActLoop` — tool-call loop
**`anima/agent/react.py:26`** — bounded round loop, anti-loop fingerprinting, tool-trace capture, token-budget compression. **Maturity: mature.** → RFC-0003 substrate.

### 5.4 `OwnerTaskAgent` — alternative execution path (overlaps 5.2)
**`anima/core/tasks.py:122`** — throws the *whole task* at one `ReActLoop(max_rounds=8)` (`:152`), no step concept; guesses approval need via keyword match (`:156-158`).
- **Maturity: usable but crude; functionally overlaps `AgentExecutor`.** See §9 #4.

### 5.5 `Pipeline` — fixed linear pipeline
**`anima/pipeline/__init__.py:67`** — 5 fixed stages (permission→memory→cognition→generation→guardrail), per-stage exception isolation, short-circuit. `StageResult` enum.
- **Maturity: mature but NOT generalizable** — no branching, no retry, no step state.

### 5.6 `CapabilityResolver` / `ToolRegistry` — dispatch substrate
- `anima/capability/resolver.py:53` `resolve()` → returns first candidate; `:7-13` explicitly lists Scorer / health ranking / fallback chain / retry as **deliberately not implemented**.
- `anima/tools/__init__.py:144` `ToolRegistry.call()` — sole execution authority.
- `CapabilityContract` declares `timeout`/`retry` (`:34-35`) but **no consumer**.
- **Maturity: skeleton (self-described "minimal skeleton").**

## 7. State machines / lifecycle

- **`IntentLedger`** (`anima/core/intents.py:47`) — "persistent intent state machine": explicit `OPEN_STATUSES`/`TERMINAL_STATUSES`, transitions with pre-state validation + immediate persist, `release(max_attempts=)` guard against infinite loops. **Maturity: mature — the most规范 FSM in the repo.** → reusable substrate.
- **`SubscriptionStore`** (`anima/monitors/subscriptions.py:25`) — generic transition FSM, dedup by `last_state`+`last_event_key`. Mature but minimal.
- **`AgentTaskStore`** (`anima/agent/state.py:70`) — on restart, `executing`→`failed` (`:80-84`); `current_step` is a resume pointer but only re-triggered by manual `approve`. **This is abandon + manual re-run, NOT auto-resume.**
- **`Checkpoint` Protocol** (`anima/contracts/lifecycle.py:36`) — **zero implementation** repo-wide. `ExecutionContextProtocol` (`:22`) ABI is mature (distinguishes `attempt` retry vs `checkpoint` resume) but unimplemented.
- `CancellationToken`/`Deadline` (`contracts/lifecycle.py:18,27`) — Protocol mature; Legacy adapter `expired()` **hardcoded `return False`** (`:199-201`, placeholder).

## 8. Scheduling / queue substrate

- **`EventBus`** (`anima/core/event_bus.py:13`) — `publish` via `asyncio.gather(return_exceptions=True)`; **no persistence, no queue, no ordering, no backpressure, no DLQ**.
- **`AgendaQueue`** (`anima/cognitive/agenda.py:64`) — atomic-persist FIFO/priority hybrid; `peek_ready` by `priority` with `not_before_at` filter. **Closest thing to a real work queue** (no claim lease / visibility timeout).
- **`IntentLedger`** — `not_before_at` (delay) + `expires_at` (TTL) + `attempts`.
- **`CalendarStore`** (`anima/cognitive/calendar.py:44`) — daily/weekly HH:MM; **closest to cron** (no cron-expression parser).
- Tick loops: `Heartbeat` (`core/autonomy.py:192`, 30s), `MonitorScheduler` (`monitors/scheduler.py:17`, 15s).
- Concurrency: only `onebot11.py:645` `Semaphore(event_concurrency)` caps channel concurrency. **`owner_agent.py:55,84` bare `create_task` per submit/approve — no cap, no backpressure.**
- ❌ **Zero `asyncio.Queue`** in `anima/`; no persistent job queue; no cron expression.

## 11. Cross-series governance collision (must be resolved before RFC-0002 scope is fixed) ⚠️

`docs/rfc/` already contains **`RFC-0106-Plan.md`** and **`RFC-0107-Execution.md`**, both marked **Anchored / frozen** — modifiable only via the Foundation Evolution Protocol (F1–F4), not by an infrastructure RFC.

They define the digital-life ontology at RFC-0100 §1.15/§1.16/§1.17:
- **RFC-0106** — *Planner = the cognitive component that decomposes a Goal into a Plan (Task graph).*
- **RFC-0106** — *Workflow = the runtime-executable form of a Plan (ordering, branching, rollback).*
- **RFC-0107 §NG1** — explicitly **excludes** scheduler / tool-executor / retry policy.
- **RFC-0107 §C4** — defers transaction / atomicity / rollback as a "0100C watchpoint" for "when a real carrier is built."

**Collision:** RFC-0002/0003 live in the **000x infrastructure series** (RFC-0000 protocol + RFC-0001 Capability); RFC-0106/0107 live in the **010x digital-life ontology series**. They use the **same three words — Plan / Workflow / Execution — with different authority boundaries.** The `Plan.branching`/`Plan.rollback` fields in `constitution/state.py:201-202` are exactly RFC-0106's reserved interface points for Workflow, and RFC-0107 explicitly does not implement them — **that empty space is RFC-0003's natural landing spot.**

This is flagged as a **finding for the reviewer, not a recommendation**. It directly affects RFC-0002's first stated focus ("define what a Plan is"): there are already three candidate "Plan" definitions (constitution `Plan`, production `AgentTask.steps`, RFC-0106 ontology), and one of them is frozen under a different governance track.

## 13. What this means for RFC-0002 (neutral observations, no prescription)

Per the reviewer's steer, RFC-0002 should stay focused on *what a Plan is, the Planner's responsibility, the Planning Interface, and Plan lifecycle*. The recon surfaces three concrete things the draft must confront (not solve here):

- **"Plan" already has 3 candidate definitions** (constitution `Plan`, production `AgentTask.steps`, RFC-0106 ontology). RFC-0002 must pick or reconcile.
- **The production `TaskPlanner` and the constitution `derive_plan` are complementary, not redundant** — a unified Planner likely merges the former's real content with the latter's structured shape. This is the natural RFC-0002 core.
- **Plan lifecycle is currently absent** — `Planner.cancel_plan` discards without archive/recovery (`constitution/planner.py:108`); production `AgentTaskStore` abandons on restart. RFC-0002's "Plan lifecycle" item has no existing implementation to extend; it is greenfield within the lifecycle concern.

The frozen RFC-0106/0107 collision (§11) is the one item that can block or reshape RFC-0002's boundary and should be decided by the reviewer before the Draft is written.
