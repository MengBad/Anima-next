# M0.5 · RFC-0003 Workflow Recon — WORKFLOW-OWNERSHIP

> **Recon discipline (per brief).** Discovery only. Facts only. This document lists **who owns,
> who modifies, who consumes, who persists** each Workflow-related state object. It does **not**
> discuss whether any of this is reasonable, correct, or should change. No recommendation.
> Attachment to (not part of) RFC-0003.

---

## 0. Notation

- **Owns** = the component that is the authoritative container / persistence root of the state object.
- **Modifies** = components that mutate the object's fields or transition its status.
- **Consumes** = components that read the object (without owning/mutating it).
- **Persists** = the file / store the object is serialized to.

## 1. `AgentTask` (+ embedded `Step`)

| Aspect | Fact |
|---|---|
| Owns | `AgentTaskStore` (`agent/state.py:70`), root = `data/agent_tasks.json` |
| Modifies | `AgentExecutor` (`executor.py:81-148`: `status`, `steps`, `current_step`, `context`, `error`); `OwnerAgent` (`owner_agent.py:81,90`: `set_status`, `request_cancel`→`_cancel`); `AgentTaskStore` (`set_status`, `save`) |
| Consumes | `OwnerAgent` (`status_text`, `_notify`); `AgentExecutor` (read `task.steps[task.current_step:]`) |
| Persists | `AgentTaskStore._save` → `agent_tasks.json` (via `PersistenceProvider`) |
| Restart recovery | `AgentTaskStore.__init__` marks any `executing` row `failed` on load (`state.py:81-84`) |

Sub-object `Step` is owned transitively by `AgentTaskStore` (serialized inside `AgentTask.steps`);
modified by `AgentExecutor` (per-step `status`/`result`/`error`).

## 9. Ownership summary (factual, no judgment)

- Each of the **4 persisted state machines** has its **own dedicated store/owner** (`AgentTaskStore`, `WorkflowStore`, `IntentLedger`, `AgendaQueue`). No shared owner observed.
- `AgentExecutor` is the **sole mutator** of `AgentTask`/`Step` runtime state; `OwnerAgent` can set status/cancel but delegates execution to `AgentExecutor`.
- The two **context protocols** are owned by different layers (pipeline runner vs constitution `ExecutionRuntime`) and split Immutable/Mutable by ADR-0002.
- **3 of 4 lifecycle primitives have no implementation** — only `ResourceBudget` is realized.
- The constitution `Plan`/`ExecutionContext` are owned within the constitution package and are **not on the production mutation path**.

No conclusion about whether this ownership layout is desirable is drawn here. Whether any of
these owners should consolidate is an **open question** (see `WORKFLOW-OPEN-QUESTIONS.md`).
