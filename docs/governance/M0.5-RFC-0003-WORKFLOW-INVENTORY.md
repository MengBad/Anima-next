# M0.5 · RFC-0003 Workflow Recon — WORKFLOW-INVENTORY

> **Recon discipline (per brief).** Discovery only. Facts only. No proposal, no recommendation,
> no evaluation of implementation quality, no comparison of approaches, no preferred direction,
> no discussion of whether RFC-0002 is correct, no RFC modification.
> Purpose: *reduce uncertainty through facts, not decisions.*

## 0. Scope note

"Workflow" in this Recon means **the set of components that orchestrate multi-step or
multi-stage activity** in the codebase — task execution, content-delivery ledgering, intent
queues, agenda queues, the reply-generation pipeline, the lifecycle/execution contracts, and
the (currently unwired) constitution planning/execution functions.

Finding up front (factual): the codebase contains **several independent state machines** that
each look "workflow-like" but serve different concerns. They are inventoried in separate
clusters below. Whether they should unify is an **open question** (see
`WORKFLOW-OPEN-QUESTIONS.md`), not a conclusion of this Recon.

## 9. Inventory summary (counts, factual)

- **4 independent persisted state machines**: `AgentTask`(+`Step`), `WorkflowRun`, `IntentRecord`, `AgendaItem`.
- **2 context protocols**: `PipelineContextProtocol` (Immutable) / `ExecutionContextProtocol` (Mutable) — split by ADR-0002.
- **3 lifecycle primitives are interface-only** (no ref impl): `CancellationToken`, `Deadline`, `Checkpoint`. One has a ref impl: `ResourceBudget`.
- **1 planning/execution cluster is implemented but unwired**: constitution `derive_plan`/`execute_plan`/`ExecutionRuntime`/`Plan`.
- **Retry is scattered** across ≥5 sites (AgentExecutor, LLM handler, channel, capability resolver, IntentLedger) — no single owner observed.
- **Queues are scattered** across ≥3 sites (`AgendaQueue`, `IntentLedger`, channel backpressure).

No conclusion is drawn from these counts. They are the raw material for
`WORKFLOW-OPEN-QUESTIONS.md`.
